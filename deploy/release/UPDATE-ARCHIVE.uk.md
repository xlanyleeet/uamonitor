# Оновлення з архіву · 2026.11.03

Готові образи для Linux amd64 (x86_64). На сервері потрібен Docker Compose v2; Git, Go, Node та збірка не потрібні. Архів не містить .env або робочих даних.

Нижче чинна інсталяція — `/opt/gradient-monitor`, Compose project — `gradient-monitor`. Перевірте їх командою `docker compose ls`: використовуйте саме чинний project і каталог із робочими `.env` та `compose.yaml`. Архітектура `uname -m` має бути `x86_64`. Збережіть старі Docker-образи; не запускайте prune до перевірки оновлення.

1. Завантажте `gradient-monitor-2026.11.03-linux-amd64.tar.gz` та файл `.sha256` на сервер, наприклад у `/tmp`.
2. Розпакуйте в окремий каталог і запустіть скрипт:

```bash
cd /tmp
sha256sum -c gradient-monitor-2026.11.03-linux-amd64.tar.gz.sha256
tar -xzf gradient-monitor-2026.11.03-linux-amd64.tar.gz
cd gradient-monitor-2026.11.03
bash update.sh /opt/gradient-monitor gradient-monitor
```

Скрипт перевіряє контрольні суми, чинний контейнер БД і Compose-конфіг, створює перевірений pg_dump у `backups/` чинної інсталяції та копію старого compose.yaml, завантажує образи, застосовує міграції, оновлює Compose і перезапускає сервіси. `.env`, пароль, volume і дані не замінюються. Під час перезапуску можлива коротка недоступність.

Якщо будь-яка команда завершується помилкою, скрипт зупиняється. Не видаляйте БД і не запускайте його з іншим project name. У цьому оновленні нової схеми БД немає: початкові міграції застосуються лише за їх відсутності.

3. Перевірте:

```bash
cd /opt/gradient-monitor
docker compose -p gradient-monitor ps
curl -fsS http://127.0.0.1:9013/api/applications/config
```

За налаштованого webhook очікується `{"enabled":true}`. Відкрийте сайт: `/add-server`, відновлення чернетки після оновлення вкладки, надсилання службової заявки, повідомлення в Discord, копіювання номера, приватне посилання на статус. Після рішення модератора оновіть статус. Старі заявки без збереженого приватного посилання не отримують нового доступу автоматично.

Зміни: нове підтвердження у стилі сайту, копіювання номера, показ контакту, чернетка у вкладці та приватна сторінка стану/причини рішення. Приватні посилання не пересилайте.

## Відкат

Скрипт друкує точний шлях резервної копії. Поверніть звідти compose.yaml і запустіть старі образи (вони мають залишатися локально):

```bash
cd /opt/gradient-monitor
# Підставте фактичний каталог, надрукований update.sh:
cp backups/applications-YYYYMMDDTHHMMSSZ/compose.yaml compose.yaml
docker compose -p gradient-monitor up -d --no-build --pull never --wait
docker compose -p gradient-monitor restart proxy
```

Відновлювати dump для звичайного відкату цього оновлення не потрібно. Не запускайте `down -v` і не перезаписуйте `.env`. Backup містить приватні дані; не публікуйте його.
